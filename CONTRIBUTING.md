# Contributing

Contributions are welcome when they improve the bootstrap workflow without turning the skill into a framework-specific monolith.

Before proposing a change:

1. Keep the core `SKILL.md` concise and platform-agnostic.
2. Put framework-specific behavior in a focused file under `references/`.
3. Prefer current official framework documentation for architectural claims.
4. Avoid adding dependencies, frameworks, or patterns as universal defaults unless there is strong justification.
5. Preserve the planning-first approval gate.
6. Keep references directly discoverable from `SKILL.md`.

For new framework support, include the decision rules for when that reference should be loaded and the minimum architecture guidance needed to bootstrap safely.
